# 状态效果函数

Paper's Brewin' 提供四个 CraftEngine 自定义 function，用于把 Brewin' and Chewin' 的酒水状态效果施加到玩家身上。它们通常挂在酒水 / 食物物品的 `consume` 事件上，喝下即生效。

四个 function 的用法完全一致，都接受 `duration`（持续 tick）和 `amplifier`（等级，0 起）两个参数，差异只在施加的效果本身：

| Function | type | 效果 |
| --- | --- | --- |
| 微醺 | `papersbrewin:tipsy_effect` | 受击伤害被「麻痹」暂存，延迟一次性结算 |
| 酩酊 | `papersbrewin:intoxication_effect` | 无法从食物中获得饱和度 |
| 狂醉 | `papersbrewin:raging_effect` | 近战命中叠层，提升攻击速度 |
| 甜心 | `papersbrewin:sweet_heart_effect` | 消耗额外饱和度缓慢回血 |

### 通用参数（YAML function）

| 参数 | 必须 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `duration` | ❌ | NumberProvider | `20` | 持续时间（tick），如 3600 = 3 分钟 |
| `amplifier` | ❌ | NumberProvider | `0` | 效果等级（0 起），负值会被截断为 0 |

:::info 等级与显示
`amplifier` 从 0 计（0 = 显示等级 I）。BossBar 标题的效果名由客户端资源包按 `effect.brewinandchewin.*` 键渲染，服务端只在其后拼接罗马等级与剩余时间。
:::

### 通用用法

```yaml
# 挂在酒水物品的 consume 事件上
events:
  - on: consume
    functions:
      - type: papersbrewin:tipsy_effect
        duration: 3600
        amplifier: 0
```

`duration` / `amplifier` 都是 NumberProvider，支持常量、区间与表达式（如 `"1200~2400"`）。

## Tipsy（微醺）

**`type: papersbrewin:tipsy_effect`**

受到攻击时，伤害不会立刻扣血，而是被「麻痹」暂存为一段虚拟血量，经过一段延迟后一次性结算为心脏骤停伤害。等级越高，可暂存的血量越多、结算延迟越长。

### 效果机制

- 最大麻痹血量随等级提升：`clamp(floor((2 + amplifier*1.6) / 2) * 2, 1, maxHealth-2)`
- 结算延迟：`ticksUntilDamage = ticks-until-damage-base + ticks-until-damage-per-amplifier * amplifier`
- III 级（amplifier ≥ `stagger.level`）起触发醉步：视角轻微飘移
- IV 级（amplifier ≥ `drunk-chat-level`）起触发醉话：聊天词内相邻字符打乱
- 可选的纯客户端反胃（屏幕扭曲），默认关闭
- BossBar 显示剩余时间与罗马等级
- ActionBar 显示当前麻痹血量

### BreweryX

若服务器装有 BreweryX 且未强制使用 PB 实现，微醺会改为向 BreweryX 醉酒系统加酒精值（每级增量由 `breweryx.alcohol-per-level` 配置），交由 BreweryX 处理衰减、醉步、醉话、反胃与昏倒。详见 config.yml 的 `effects.tipsy.force-papersbrewin`。

### 使用例

```yaml
events:
  - on: consume
    functions:
      - type: papersbrewin:tipsy_effect
        duration: 3600
        amplifier: 2      # 显示等级 III，起触发醉步
```

## Intoxication（酩酊）

**`type: papersbrewin:intoxication_effect`**

效果期间，玩家进食只回饥饿值，饱和度增量被清零——吃东西不再「顶饱」。

### 效果机制

- 进食时饱和度增量归零，饥饿值正常恢复
- BossBar 显示剩余时间与罗马等级

### 使用例

```yaml
events:
  - on: consume
    functions:
      - type: papersbrewin:intoxication_effect
        duration: 2400
```

---

## Raging（狂醉）

**`type: papersbrewin:raging_effect`**

效果期间，蓄力充足的近战命中会叠加层数，按层数提升攻击速度；层数随时间衰减。

### 效果机制

- 只有蓄力比例超过 `min-attack-strength`（默认 0.8）的近战命中才叠层
- 层数上限 `max-stacks`（默认 4）
- 攻击速度加成：`min(cap, per-stack * stacks + per-amplifier-per-stack * amplifier * stacks)`，上限 `attack-speed-cap`
- 层衰减计时 = `ceil(reset-tick-multiplier * 攻击蓄力延迟)`
- 命中叠层时按层数生成粒子，ActionBar 显示当前层数
- BossBar 显示剩余时间与罗马等级

### 使用例

```yaml
events:
  - on: consume
    functions:
      - type: papersbrewin:raging_effect
        duration: 2400
        amplifier: 1
```

## Sweet Heart（甜心）

**`type: papersbrewin:sweet_heart_effect`**

效果期间，玩家定期消耗饱和度缓慢回血。

### 效果机制

- 回血间隔：`heal-interval-base >> amplifier`（等级越高越频繁，对齐原版 `20 >> amplifier`）
- 每次回血量上限 `heal-per-tick`（默认 1.0），同时消耗等量饱和度
- BossBar 显示剩余时间与罗马等级

### 使用例

```yaml
events:
  - on: consume
    functions:
      - type: papersbrewin:sweet_heart_effect
        duration: 2400
        amplifier: 1      # 回血更频繁
```

## 配置与外观

四个效果的机制参数、BossBar 外观与开关都在 `config.yml` 的 `effects` 段配置，例如：

```yaml
effects:
  tipsy:
    enable: true
    bossbar:
      show: true
      color: PURPLE            # BLUE, GREEN, PINK, PURPLE, RED, WHITE, YELLOW
      style: SEGMENTED_10      # SOLID, SEGMENTED_6, SEGMENTED_10, SEGMENTED_12, SEGMENTED_20
    ticks-until-damage-base: 200
    ticks-until-damage-per-amplifier: 20
    # …醉步、醉话、反胃等子项
  intoxication:
    enable: true
    bossbar: { show: true, color: GREEN, style: SEGMENTED_10 }
  raging:
    enable: true
    bossbar: { show: true, color: RED, style: SEGMENTED_10 }
    max-stacks: 4
    attack-speed-cap: 0.8
  sweet-heart:
    enable: true
    bossbar: { show: true, color: PINK, style: SEGMENTED_10 }
    heal-interval-base: 20
    heal-per-tick: 1.0
```

各字段的完整含义见配置文件内的注释。ActionBar 反馈文案可在 `lang/<语言>.yml` 中自定义（如 `effect_tipsy_actionbar`、`effect_raging_actionbar`）。

:::note
若某效果在 config.yml 中 `enable: false`，对应的 function 施加将不产生表现（BossBar / 反馈不显示）。
:::
